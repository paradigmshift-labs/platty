# 앵커 후보 확인과 되묻기

도구로 알 수 있는 사실은 묻지 않고 먼저 조회한다. 단, 질문의 낱말이 가리키는 **메뉴·화면·API·배치·테이블·컬럼 후보가 세는 기능 묶음(1절)으로 둘 이상**이면 조사 전에 어느 것인지 먼저 묻는다. 같은 낱말이 여러 메뉴에 있으면(예: 이름에 같은 낱말이 들어간 등록 화면이 둘) 답이 달라지고, 한쪽으로 가정해 조사하면 사용자가 원하지 않은 쪽을 길게 조사하게 된다. 답이 짧아질지 길어질지는 묻지 않을 이유가 아니다.

## 1. 후보 찾기 (질문에 정확한 식별자가 없을 때)
- 메뉴·화면 낱말: `menu_lookup(text)`와 `term_lookup(text, view: "summary", limit: 10)`. 후보는 두 결과의 합집합이다.
- API·URL 낱말: `route_resolve(query)`. 배치 이름: `job_dependency_trace({text})`.
- 테이블·컬럼 낱말: `term_lookup`의 주소(`테이블.컬럼`). 같은 낱말이 여러 테이블에 있으면 각각 후보다.
- term_lookup 주소 테이블은 후보 행의 "대상" 칸에 적는다. 주소 테이블을 쓰는 화면을 따로 행으로 올리는 것은 menu_lookup에서 질문 낱말과 맞는 메뉴가 0개일 때, 또는 질문 낱말이 컬럼·코드값·데이터 목록을 가리킬 때만이다. 한정어 불일치 사유 밖으로는 이름으로 거르지 않는다.
- 질문에 정확한 식별자(화면 ID, SQL id, 전체 URL, 테이블 이름)가 있고 결과가 하나면 묻지 않는다.
- 같은 기능의 복사본(`design/`·`sample/` 사본, 같은 화면의 다른 채널)은 한 후보로 묶고 묶었다고 한 줄 쓴다. 메뉴 경로나 화면 title이 다른 것은 묶지 않는다.

후보 표 (조사한 범위에 그대로 싣는다. 행이 없으면 `후보 없음(조회한 낱말)`):
```
조회한 낱말: <menu_lookup·term_lookup에 넣은 낱말들>
질문이 알려는 것: <화면 위치 / 데이터 값·출처 / 처리 동작·규칙 / 변경 영향> · 동작어: <질문의 동사, 없으면 없음> · 한정어: <질문이 붙인 상태·단계·소유 낱말, 없으면 없음>
| 번호 | 후보 (메뉴 경로 > 화면 title, 화면 ID 또는 API. 데이터면 `데이터: 업무 이름(테이블)`) | 하는 일 (조회·표시 / 처리·전송 / 미확인) | 대상 (처리·전송이면 저장·전송 API 또는 서비스 메서드, 조회·표시면 읽는 테이블) | 기능 묶음 | 세는가 (예 / 아니오: 사유) | 찾은 곳 |
판정: 세는 기능 묶음 n개 → 묻는다 / 묻지 않는다(사유)
비대화형 선택: <번호> — 사유: <메뉴 이름 정확 일치 / 질문의 동작어를 처리하는 대상이 이 행에만 있음 / 표 순서>
```
- 기능 묶음: 같은 처리 진입(같은 저장·전송 API 또는 같은 서비스 메서드)을 부르는 화면·배치·외부 호출자는 한 묶음이다(한 기능을 여러 곳이 가리키는 경우). 처리 진입이 다르면 같은 테이블을 써도 다른 묶음이다. 질문이 알려는 것이 화면 위치나 데이터 값·출처이면 같은 테이블을 읽는 행은 한 묶음이다.
- 세는가의 아니오 사유는 셋뿐이다: `n번과 같은 묶음` / `조회 질문인데 처리·전송 행`(질문이 알려는 것이 화면 위치·데이터 값이고 이 행의 하는 일이 처리·전송일 때만) / `한정어 불일치(<한정어> / 이 행의 대상)`(이 행의 대상 테이블이나 화면 title이 한정어와 다른 상태·단계·소유임을 이미 받은 조회 결과로 보일 때만). 아니오 행은 `다른 읽기`에 쓴다.
- 하는 일·대상은 화면 title과 이미 받은 조회 결과로만 채운다. 못 채우면 `미확인`으로 두고 `예`로 센다. 이 칸을 채우려고 호출을 더하지 않는다.

## 2. 묻는 조건
| 후보 | 하는 일 |
|---|---|
| 세는 기능 묶음이 2개 이상(묶음은 1절 칸 규칙: 처리 진입이나 읽는 테이블이 다름) | **항상 묻는다.** 길이나 "전부 답해도 된다"는 이유로 건너뛰지 않는다 |
| 1개 | 묻지 않고 해석 줄에 어느 것인지 쓴다. 유사 문자열(fuzzy)로만 찾았으면 하나여도 확인한다 |
| 0개 | 질문의 낱말을 바꿔 한 번 더 조회하고, 그래도 없으면 어느 메뉴에서 보던 화면인지 묻는다 |

의도(조회/변경 등)나 범위(무엇을 어디까지)가 갈리는 경우는 후보마다 답이 달라 한 번에 답하면 흐려질 때만 묻는다. 한 턴에 모호성 하나만 묻는다.

## 3. 질문 형식
- 선택지는 후보 표의 행에서만 고른다(행 번호를 붙인다). 범위·방식 해석은 선택지로 쓰지 않는다. 후보를 고른 뒤에도 갈리면 따로 한 번 묻는다. 선택지 2~4개 + `목록에 없음` (대화형이면 선택 도구를 쓴다), 서로 겹치지 않게 쓴다.
- 선택지마다 후보 표의 후보 칸과 대상 칸을 함께 쓴다: 화면 행은 "메뉴 경로 > 화면 title (화면 ID) — 대상: <대상 칸의 업무 이름>", 데이터 행은 "데이터: <업무 이름>(테이블) — 쓰는 화면: <이미 받은 조회 결과의 메뉴 경로들>". 다른 후보와 구분되는 점은 이 칸 값에서만 가져온다. 같은 계열 후보를 먼저, 이름만 비슷한 기능은 `목록에 없음` 근처에 쓴다.
- 후보가 4개를 넘으면 먼저 상위 메뉴 그룹을 묻고(`menu_lookup`의 `parentMenuId`로 다음 단계를 본다), 고른 그룹 안에서 화면을 묻는다. 후보를 임의로 4개로 자르지 않는다.
- 질문 외에 후보가 무엇을 하는지 설명하거나 원인을 암시하는 말은 쓰지 않는다.

## 4. 답을 받은 뒤
- 하나를 고르면 그 후보를 앵커로 확정하고 조사한다.
- `전부`를 고르면 후보별로 나눠(최대 3개) 각각 메뉴 경로를 머리에 붙여 답한다.
- `목록에 없음`이면 보던 메뉴나 화면 이름을 자유 입력으로 한 번 묻고 다시 조회한다. 그래도 정해지지 않으면 찾지 못했다고 답한다.
- 같은 모호성은 두 번 묻지 않는다.
- **비대화형 실행**(질문 목록, 테스트)에서는 묻지 않는다. `비대화형 선택` 줄의 후보로 조사하고, `해석:` 줄에 어느 후보인지 쓰고, `다른 읽기:`에는 후보 표의 나머지 행 번호와 메뉴 경로를 모두 쓴다(`후보 없음`은 표가 0~1행일 때만). 조사한 범위에 `되묻기 필요: <무엇을>`을 쓴다.

예시 (가상) — 사용자: 쿠폰 등록 규칙 알려줘

스킬: "쿠폰 등록"에 해당하는 화면이 둘 있습니다. 어느 것을 말씀하시나요?
1. `쿠폰 관리 > 일반쿠폰 등록` (`CPN2010`) — 대상: 일반쿠폰 등록 저장
2. `쿠폰 관리 > 이벤트쿠폰 등록` (`CPN2020`) — 대상: 이벤트쿠폰 등록 저장
3. 목록에 없음

**확정된 내용**: 되묻기를 거쳤으면 답의 끝에 `확정된 내용` 블록(질문 / 대상 / 범위 세 줄, 예: `- 대상: 쿠폰 관리 > 이벤트쿠폰 등록(CPN2020)`)을 쓴다. 사용자가 고치면 고친 내용이 처음 쓰이는 단계부터 다시 한다. 그 대화 안에서만 쓰고 저장하지 않는다. 코드·문서에 없는 운영 사실이 나오면 "메모리에 추가할까요?"라고 제안만 하고, 사용자가 명시적으로 요청할 때만 메모리 요청을 올린다.
