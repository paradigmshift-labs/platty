# 인터랙션과 검증

버튼을 작동시키거나 HTML 프로토타입을 만드는 요청에만 이 문서를 읽는다.

## 상태 모델

화면마다 `현재 상태 → 사용자 행동 → 성공/실패 결과 → 화면 변화`를 FSD ID와 함께 적는다. 지원되지 않은 결과는 프로토타입에서 성공처럼 꾸미지 않는다. 목적지 화면이 범위 밖이면 실제 이동인 척하지 말고 **화면 밖**에 대상 이름과 범위 표시를 둔다. 미정 목적지는 하나로 대체하지 않는다.

실제 데이터가 필요한 값은 정확한 출처를 확인한다. 예시 데이터라면 예시임을 화면 밖에 적고, 예시 항목의 고유 ID를 사용한다. 표시된 샘플 행 수를 전체 카운트로 간주하지 않는다. 필터 선택은 동일한 데이터 집합의 해당 부분을 보여주며 빈 상태를 임의 목록으로 바꾸지 않는다. 읽음·이동·업무 완료처럼 독립된 결과는 별도 상태로 유지하고, 확인된 성공에만 화면을 바꾼다. 재시도·지연·실패·복귀는 FSD가 정의한 경우만 시뮬레이션한다.

## 완료 전 확인

| 확인 대상 | 통과 기준 |
| --- | --- |
| FSD 커버리지 | 각 화면·영역·정보·상태·예외·행동 ID에 대응 화면 또는 명시적 범위 밖 사유가 있다. |
| 출처 | 핵심 문구·이미지 자리·수치·목적지·상태 전이에 FSD 또는 확인된 현행 코드 근거가 있다. 임시 문구는 화면 밖에서 표시한다. |
| 중복·추가 | 의미 요소마다 필요한 횟수만 나타난다. 참고 이미지의 콘텐츠와 UX가 새 요구사항으로 섞이지 않았다. |
| 정보 위계 | 화면 사이뿐 아니라 같은 화면의 섹션·행 안에서도 핵심 결정 정보가 주변 정보보다 먼저 인지된다. |
| 색 | 사용된 모든 명시 색이 시각 언어 계약의 13개 HEX이며, SVG·인라인 스타일·상태 변화도 같다. |
| 인터랙션 | 모든 클릭 결과가 상태 모델과 일치하고, 중복 처리·실패·빈 상태·복귀에서 임의 성공이나 데이터 생성이 없다. |
| 접근성 | 버튼 이름, 포커스, 키보드 조작이 가능하고 조작 요소가 중첩되지 않는다. |
| 표현의 한계 | 예시 데이터, 색상 근사, 미정 정책, 범위 밖 목적지가 제품 사실로 오인되지 않게 화면 밖에 기록돼 있다. |

짧은 화면 확인과 핵심 전이 테스트로 실제 산출물을 검증한다. 검증하지 못한 항목은 결과 보고에 그대로 적는다.
