# 조사 도구 — 코드에서 팩 근거를 만든다

`build-pack.py`는 상류 산출물을 정규화할 뿐이고, 그 산출물을 **실제 앱 소스에서 만들어
내는 것**이 여기 있는 도구다. 팩에 화면 근거가 없거나 컴포넌트가 비어 있으면 원인은
거의 이쪽이다.

모든 도구는 특정 저장소나 팩에 묶여 있지 않다. 범위(`--scope`)와 대상 커밋만 바꾸면
다른 화면군, 다른 팩 버전에 그대로 쓴다.

## 순서

```
extract-screens  →  capture-screens  →  publish-captures  →  build-pack  →  coverage
     코드 사실          실행 캡처          팩 근거로 반입         팩 빌드       팩과 대조
```

미리보기와 보고서는 언제든 따로 돌린다.

## 도구

| 도구 | 하는 일 | 필요한 것 |
| --- | --- | --- |
| `extract-screens.mjs` | 라우트별 컴포넌트·클래스·상태·API·문구를 구문 분석으로 추출 | 앱 체크아웃, 그 앱의 `node_modules`(TypeScript) |
| `capture-screens.mjs` | 라우트를 실제로 띄워 전체 페이지 캡처, 렌더 판정 기록 | 실행 중인 앱, playwright |
| `publish-captures.py` | 캡처를 상류에 참조 근거(`inventory/runtime-captures.json`)로 반입 | 조사 산출물, 상류 체크아웃 |
| `coverage.py` | 추출 결과를 팩·Platty 스펙과 대조해 격차를 센다 | facts, `pack.json` |
| `build-component-preview.mjs` | 실제 구현을 렌더해 컴포넌트 미리보기와 검토 화면용 사이드카 생성 | 앱 체크아웃, `pack.json` |
| `flutter-parity.py` | Flutter HDS의 토큰·컴포넌트를 팩과 대조 | HDS 체크아웃, `pack.json` |
| `build-gallery.py` | 캡처를 한 장으로 보는 로컬 갤러리 | 캡처 산출물 |
| `build-report.py` | 조사 결과 보고 페이지 | facts, captures, coverage |

각 도구는 `--help` 없이도 인자 이름이 곧 설명이다. 인자를 빠뜨리면 무엇이 필요한지
말하고 멈춘다.

## 규칙

- **산출물은 저장소에 넣지 않는다.** 캡처에 실제 상품·화면 내용이 들어간다. 조사 결과는
  작업공간의 무시되는 폴더에 두고, 팩으로 반입한 것만 전달물로 나간다.
- **캡처는 승인이 아니다.** 그 커밋의 코드가 만들어 낸 결과이고, 팩에 들어갈 때도 그렇게
  표시된다. 디자이너가 승인한 화면과 섞지 않는다.
- **렌더하지 못한 화면은 지우지 않는다.** 이유를 단 행으로 남긴다. 빠진 근거는 읽을 수
  있어야 고칠 수 있다.
- **미리보기의 변형 값은 팩의 닫힌 계약에서만 가져온다.** 계약에 없는 값을 그리면 그
  화면은 거짓이 된다.
