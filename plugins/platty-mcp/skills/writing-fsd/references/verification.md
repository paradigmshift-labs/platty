# FSD 검수와 전달 판정

## 문답 검수

1. 각 변경 화면의 제품·디자인 결정 축에 근거 있는 답, 명시적 보류, 사실 확인 필요, 해당 없음 중 하나가 붙었는가? 측정·이벤트를 질문 축에 섞지 않았는가? `추천`·사전 선택·무응답을 확정으로 바꾼 항목이 없는가?
2. 질문마다 판단 하나인가? 8~10개 관련 질문을 한 번에 제시했는가? 질문 UI가 실제로 눌리고 미응답 상태를 보존했는가? 자동으로 닫힌 질문의 동일 번호·선택지를 복원했는가?
3. AI 추천의 근거·반론·손실과 사람의 최종 선택·선택 이유를 분리했는가? 새 답변이 이전 규칙, 화면, 시나리오와 AI가 도출한 과정지표에 전파되었는가?
4. 선택이 필요한 화면 예외와 경로를 AI가 편의상 만들지 않았는가? 기존 문서에서 이미 정한 답을 반복 질문하거나, 연결만 되는 변경 없는 화면을 중복 설계하지 않았는가?

## 사람의 화면 디자인 점검

FSD의 4장과 연결된 규칙만 읽고 새로운 사람이 **기본 화면과 예외 상태를 그리게** 한다. 영역 순서, 상하·좌우·포함 관계, 그룹, 주 행동, 정확한 문구, 상태별 추가·변경·숨김, 긴 문구·결측·좁은 화면·큰 글씨를 알아낼 수 있는지 본다. 그릴 때 선택해야 하는 지점은 질문 또는 `미결정`으로 되돌린다. 와이어프레임 유무로 점수를 대신하지 않는다.

## 개발자·구현 AI의 전달 점검

새 독자가 FSD와 명시된 참조 자료만으로 대표 흐름 하나를 따라가며 `현재 상태 → 사건 → 화면 반응·이동 → 다음 상태`를 재구성하게 한다. 시간 경계, 반복·동시 조작, 실패·취소·뒤로·복귀, 데이터 없음·변경, 정보·선택의 유지에서 제품 판단을 추측해야 하면 보완한다. 내부 API·DB·캐시·SDK 방식이 FSD의 필수 규칙으로 들어갔다면 사용자에게 보이는 결과와 분리한다. 기술 담당자의 내부 구현 선택만 남은 경우에는 FSD 자체를 미완료라고 하지 않는다.

## 문서 일관성 점검

- 최신 PRD·JTBD·사용자 정정을 적용했는가? 다른 프로젝트의 Q&A·정책·문구를 기본값처럼 복사하지 않았는가?
- 모든 ID가 고유하고 참조가 실제 대상에 닿는가? 하나의 규칙을 한 곳에서 정의하고 다른 곳에서는 ID로 연결했는가?
- 현재 사실·설계 가설·AI 제안·사람의 확정·기대 시나리오·실제 검증 결과의 상태를 섞지 않았는가?
- 정상·경계·예외·복귀 시나리오가 규칙 ID를 가리키는가? 시나리오를 테스트 통과라고 주장하지 않았는가?
- 부록 A의 과정지표가 PRD 목표·FSD 가설·화면·동작·상태 ID에 닿고, 대상·분자·분모·관찰 범위와 해석 한계를 설명하는가? 주요 이탈 지점을 구별하는 최소 지표만 골랐는가?
- 측정 의도를 AI가 직접 정하고 별도·일반 문답 어디에서도 측정 질문을 하지 않았는가? FSD가 이벤트 이름·발생/제외·속성·수집 방식 등 개발자의 텍소노미를 대신 설계하거나 계측 가능성을 확인한 것처럼 쓰지 않았는가?
- 제목 계층·불렛 들여쓰기·짧은 문장·쉬운 용어가 사람의 이해를 돕고 ID·조건·관계는 보존하는가?
- 원본 Markdown/Codex와 실제 게시한 Notion 등 **전달한 각 환경**의 목차와 참조 링크를 클릭해 확인했는가? 검증할 수 없는 환경은 그대로 적었는가?

## 결과 표시

`문답 완료`, `사실 확인 대기`, `FSD 초안`, `범위별 개발 전달 가능`, `구현 결정 대기`를 별도로 보고한다. 필수 제품 선택이 남은 화면·동작과 영향은 ID로 적는다. 미결 외의 확정 범위는 계속 작성한다.
