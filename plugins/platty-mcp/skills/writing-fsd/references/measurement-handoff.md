# 과정지표와 측정 의도 인계

## 책임

PRD는 프로젝트의 **최종 목표·성공 기준**을 제공한다. FSD 작성 AI는 그 목표에 이르는 화면·행동·상태의 흐름을 바탕으로 **무엇을 관찰하면 설계가 작동하는지 판단할 수 있는가**를 결정한다. 사용자에게 측정 목적, 지표, 이벤트, 집계, 속성, 계측 가능성을 묻지 않는다. 개발자는 이 인계 내용을 보고 실제 이벤트 텍소노미를 설계한다.

## 도출 절차

1. 승인된 PRD의 목표·대상·성공 기준 ID를 적는다. 목표가 정량화되지 않았으면 목표 문구를 그대로 참조하고 수치·목표치를 만들지 않는다.
2. FSD의 흐름·화면·동작·상태 ID로 목표에 이르는 핵심 경로를 잇는다. 각 전환에서 사용자가 보게 되는 기회, 선택, 진행, 완료, 실패·복구 중 실제로 정의된 것만 찾는다.
3. 다음 기준을 모두 만족하는 **최소한의 과정지표**를 고른다: PRD 목표나 FSD 가설과 직접 연결됨; 주요 이탈·실패 지점을 구별함; 정의된 행동·상태로 관찰 가능함; 값이 달라졌을 때 어떤 설계를 살펴볼지 알 수 있음. 모든 버튼·상태에 지표를 만들지 않는다.
4. 각 지표의 **대상·분모가 되는 기회·분자가 되는 행동/결과·관찰 범위**를 사용자 경험의 말로 정한다. 비교가 필요한 사용자 상황·진입 경로·상태가 FSD에 있으면 기록한다. 횟수와 사람 수처럼 해석이 달라지는 단위는 측정 목적에 맞춰 개념적으로 정하되, 이벤트 발생·중복 제거의 기술 규칙은 개발자가 설계한다.
5. 지표가 답하는 질문과 답하지 못하는 질문을 함께 쓴다. 표시 ≠ 읽음·이해, 버튼 선택 ≠ 과업 완료, 기록되지 않은 외부 결과 ≠ 성공이다. 이해 검증이 필요하면 행동 지표로 대신하지 말고 별도 확인 방법을 적는다.

PRD 목표나 FSD 근거가 모호해도 **측정 문답을 새로 열지 않는다**. 주어진 문구에 가장 충실한 해석으로 도출하고, 근거가 부족한 부분과 계산에 미치는 영향을 부록 A에 표시한다. 관찰할 수 없는 결과는 측정된 것처럼 쓰지 말고 필요한 외부 자료나 대리 지표의 한계를 적는다. 지표 선정은 AI가 맡으며, 사람의 답변을 받았다고 표기하지 않는다.

## 부록 A의 작성 계약

각 `MEAS-` 행에 `PRD 목표 ID → 확인하려는 판단·FSD 가설 ID → 과정지표 → 대상·분자·분모·관찰 범위 → 관련 화면·동작·상태 ID → 해석 한계`를 연결한다. AI가 도출한 **측정 요구**로 인계하며, 실측 결과나 계측 가능성 확인으로 표시하지 않는다. 11장에서는 기대 효과와 `MEAS-` ID를 연결하고 부록 A의 정의를 반복하지 않는다.

**개발자 인계:** 이 측정 요구를 충족하도록 기존 이벤트 재사용 여부, 신규 이벤트의 이름·의미, 정확한 발생·제외 조건, 재노출·재진입·반복 조작의 처리, 속성·허용값, 수집 위치·방식, 계측 가능성과 검증 방법을 설계한다. FSD는 이 이벤트 명세를 대신 작성하지 않는다. 불가능하거나 목표의 뜻이 달라지는 경우 개발자가 이유와 가능한 대안을 남겨 후속 조정한다. 계측 가능성 미확인만으로 화면·동작의 FSD 전달을 막지 않는다.

## 예시: 신청 완료 증가

PRD 목표가 `신청 완료 증가`이고 FSD가 `알림 카드 표시 → 상세 진입 → 신청 화면 진입 → 신청 완료`를 정의했다면 다음처럼 핵심 전환을 구분한다.

| ID | 확인할 판단 | 과정지표의 뜻 | 근거 | 해석 한계 |
| --- | --- | --- | --- | --- |
| MEAS-01 | 알림에서 상세로 넘어가는가 | 알림 카드가 화면에 표시된 대상 중 상세에 진입한 비율 | PRD 목표, 카드 표시 상태·진입 동작 ID | 표시를 읽음·이해로 해석하지 않음 |
| MEAS-02 | 상세 이후 신청을 마치는가 | 상세에 진입한 대상 중 신청 완료 상태에 도달한 비율 | PRD 목표, 상세·신청·완료 상태 ID | 신청 버튼 선택을 완료로 해석하지 않음 |

이 표의 ID·문구는 설명용이다. 실제 FSD에서는 승인된 PRD와 해당 프로젝트의 FSD ID·경로만 사용한다.
