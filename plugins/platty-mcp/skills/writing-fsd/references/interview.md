# FSD 문답 기준

## 1. 근거와 결정 공백

사용자의 최신 지시·명시적 정정을 우선하고, 승인된 PRD·JTBD·User Story와 디자인시스템은 버전·항목 ID로 인용한다. 현행 화면·코드·Platty는 **현재 사실**을 확인하는 자료다. 확인되지 않은 현재 동작을 사실처럼 말하지 않는다. 옛 FSD는 이력 확인에만 쓰고 최신본의 형식 평가 기준으로 삼지 않는다.

현재 사용자 이해(대상·관계·행동 결과·상태 변화·정보 유지/삭제·오류 예상) → 목표 개념모델(대상·속성·관계·가능 행동·결과·규칙) → 화면의 명칭·정보·배치·피드백·복구를 연결한다. 관찰 사실과 기획자의 추정을 구별한다. 사용자가 목표 개념을 이해했는지의 검증 기준은 클릭·완료와 별도로 정한다.

각 변경 화면에 대해 `영역·요소 × 사용자·진입 경로 × 상태 × 행동`을 살핀다. 모든 조합을 질문하지 않는다. 답에 따라 보이는 경험이 달라지고 기존 자료에 답이 없는 조합만 **독립 결정**으로 등록한다. 결정 공백 대장의 최소 필드: 질문 ID, 화면·요소·규칙 ID, 공백의 정확한 내용, 왜 결과가 달라지는지, 근거, 답변 상태, 최종 답변·답변자, 영향받는 FSD 위치, 변경 이력. 답이 있는 축에는 근거 ID, 해당 없는 축에는 이유를 남긴다.

| 점검 축 | 반드시 찾아볼 선택 |
| --- | --- |
| 화면 구성 | 요소 유무·그룹·순서·상하/좌우·포함 관계·강조·문구·기존 요소와 관계 |
| 사용 상황 | 대상 사용자·권한·진입 경로·첫 방문·재방문·재진입 |
| 정보 | 의미·단위·표기·길이·없음·오래됨·갱신 기준 |
| 조작 | 탭·입력·선택·스크롤·뒤로·취소·반복·동시 조작·목적지 |
| 시간 | 시작점·값/단위·경계·중단·초기화·재시작·이탈/복귀·겹침 |
| 상태·복구 | 최초·진행·로딩·빈 값·완료·부분 성공·실패·상태 변경·복구 |
| 표현 환경 | 긴 글·큰 글씨·좁은 화면·이미지 없음·읽기 보조·포커스·읽는 순서 |

질문 대장은 ① 설계 전제 ② 상대적 우선순위 ③ 대안 비교·선택 ④ 조건·동작 ⑤ 반론·재검토 ⑥ 정상·경계·예외·복귀 시나리오를 점검한다. FSD 장 순서대로만 질문하지 않는다. 각 답변 뒤 새 분기·충돌·예외를 다시 찾는다. 현행 서비스 사실 확인, 사람의 정책·디자인 결정, 개발자의 기술 결정을 분류한다. 내부 방식(`슬롯을 잠근다`, `DB에 저장한다`)을 사용자 경험 규칙처럼 제안하거나 질문하지 않는다. 측정·이벤트 관련 선택은 질문 대장에 넣지 않는다. 화면·동작이 정리되면 [측정 의도 인계 기준](measurement-handoff.md)에 따라 AI가 직접 도출한다.

## 2. 추천하고 질문하는 법

각 요소·조합에 대해 `역할 → 필요한 이해·행동 → 효과를 낼 이유 → 예상 결과 → 반론·대안`을 검토한다. **역할의 중요도**, **효과의 개연성**, **시각적 우선순위**는 다른 판단이다. 근거 없는 점수·확률을 꾸미지 않는다. 목표 기여·선후 관계·학습 부담·혼동 가능성·공간 제약·디자인시스템을 비교한다. AI가 적극적으로 추천하고 필요하면 사람의 선택에 반론을 제시하되, 최종 제품·디자인 선택과 허용할 손실은 사람이 결정한다. 추천 이유를 사람의 선택 이유로 바꾸어 기록하지 않는다. 새 근거가 나오면 추천을 갱신한다. 후보가 확인되지 않은 서비스 가능성·운영 허용 범위에 의존하면 **조건부 후보**로 표시하고 먼저 사실을 확인한다. 그 사실을 확인하기 전에는 실현이 보장된 `추천`으로 표시하지 않는다.

한 차례에 관련 독립 질문을 가능한 한 많이, 보통 **8~10개 안팎** 묻는다. 질문 수를 채우려고 무관한 항목을 붙이지 않는다. `이 그룹의 추천안을 모두 적용`처럼 여러 결정을 한 번에 승인시키지 않는다. 질문 하나는 구체적 상황 → 단일 판단 → 2~3개 구분되는 선택지(추천 표시·각 이유·손실) → 직접 답변 경로로 쓴다. 디자인·개발 용어가 없으면 이해할 수 없는 질문은 화면 예시로 다시 표현한다. 자유 입력이 필요한 질문은 그 이유와 필요한 정보를 명확히 한다. 질문 번호는 안정적으로 유지한다.

**클릭형 문답 계약:** 사용자가 요청한 기본 질문 창을 우선한다. 질문 본문, 누를 수 있는 번호 선택지 행, 현재 순서, 앞·다음 이동, 직접 답변, 명시적 건너뛰기를 제공할 수 있는 도구를 쓴다. 도구가 일부 기능만 지원하면 가능한 인터랙션을 정확히 설명한다. 건너뛰기는 보류다. UI가 자동으로 사라져도 질문은 미응답이고 같은 번호·선택지를 복원한다. 반복되면 지속되는 클릭형 화면을 사용하고 실제 선택·제출이 되는지 확인한다. 채팅 텍스트는 복구 보조 수단이다. 클릭형 도구가 전혀 없으면 한계를 알리고 형식 충족이나 문답 완료를 주장하지 않는다. 사전 선택, 침묵, 시간 경과, UI 닫힘은 결코 수락이 아니다.

답변마다 `확정/보류·미결/사실 확인 필요/해당 없음`으로 기록한다. 명시적 정정은 대체된 질문·규칙·시나리오에 전파하고, 그에 연결된 과정지표도 다시 도출한다. 진행도는 사용자가 요청한 범위와 확인된 질문 수를 분모로 하며, 미래 질문까지 안다는 듯한 완료율을 만들지 않는다. 문답 중 문서 수정을 보류하라는 지시가 있으면 종료까지 원본 FSD를 수정하지 않는다.

## 3. 종료와 재개

알려진 화면·상태·규칙을 다시 훑어 사람에게 물어야 할 공백이 없을 때 문답을 끝낸다. 의도적 보류와 외부 사실 확인은 대장에 남긴다. 필수 선택이 남으면 해당 범위를 `구현 결정 대기`로 표시한다. 답변 없이 임의 적용한 초안을 전달 가능한 FSD로 취급하지 않는다.
